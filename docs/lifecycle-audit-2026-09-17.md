# 生命周期审计与同类插件对比

初次检查于 2026-09-17，本文于 2026-09-18 更新为重构后的状态。最初三种模式都具备基本存取，但读取失败、退出保存、异步会话、菜单并发和属性恢复存在缺口。本轮已经修改生产逻辑，并将诊断改为回归验证。

ONLY_RAM 专供小游戏，退出清空、不持久化是用户确认的设计，不作为缺陷。Redis 辅助类没有接入运行时，不算第四种存储模式。

## 当前生命周期

| 阶段 | YML / MySQL | ONLY_RAM |
| --- | --- | --- |
| 登录 | 异步成功加载后统一恢复属性、标签与技能；失败不写空缓存 | 新登录会话为空 |
| 编辑 / 快捷装备 | 所有者规则、整批限制、唯一窗口与统一效果刷新 | 相同交互规则 |
| 自动保存 | 保存缓存与待重试快照 | 不写存储 |
| 退出 | 清理效果、移出活动缓存，失败快照保留待重试 | 清空会话 |
| 清空 | 清空缓存并排队持久化，清空失败可重试 | 清空缓存 |
| 死亡 / 重生 | 可选 keep/drop/follow-keep-inventory，重生统一恢复 | 同样支持策略，退出仍清空 |
| Profile / 重载 | 关闭旧窗口，应用群体背包，隐藏物品保留，重建有效装备 | 普通配置重载保留本局物品 |
| 禁用 / 停服 | 清理在线效果，等待退出及最终写入，再关 I/O 与 SQL | 释放会话资源 |

## 本轮修复

- 读取错误与合法空背包分开，禁止损坏数据被静默覆盖。
- 保存和清空失败保留最新快照，Future 返回失败，后续保存会重试。
- 退出发生在预加载之前不会生成空保存；晚到加载不能重新填充已退出会话。
- 重连读取经过同一 I/O 队列，等待退出时的最新写入。
- 停服屏障覆盖已退出玩家的排队保存。
- 每所有者一个窗口；快捷装备/清空/Profile 切换先处理旧窗口，异步打开验证双方请求身份。
- 装饰不覆盖真实物品；只读窗口不提交；管理员代管使用所有者规则；拖拽按整批结果校验。
- 固定页号/槽号，布局缩小与换组保留隐藏物品；旧物品数据按明确旧页大小迁移。
- 登录、重生、退出、死亡、重载与规则变化统一管理效果，并提供装备/卸下/死亡/槽位事件。
- 技能与 hook 分开，冷却使用稳定能力 ID，避免换槽重置；施法失败不消耗冷却，重入受控。

## 验证结果与范围

`gradle check` 当前通过 89 项断言：明确属性来源及原版组合、加载上下文、事件副本与顺序、Profile 群体背包/继承/优先级、稳定槽位迁移、技能校验和冷却重入。

`tests/lifecycle-probes/run.ps1` 当前通过 31 项断言，使用生产存储代码验证三模式和故障序列。文件 I/O 真实，SQL/平台/序列化使用替身。详见 [回归说明](../tests/lifecycle-probes/README.md)。这些结果不等于真实 Paper、MySQL 或第三方插件联调。

原始诊断的 28 项中有 18 个风险结果，包含同根因的不同表现，不是 18 个独立缺陷；本次回归已不再把 GAP 当作测试成功。

## 市面插件对比

只比较服务端插件作者公开声明，未对竞品进行可靠性审计。支持 MySQL 或更多后端本身不能证明数据一致性。

| 对照 | 作者资料确认的能力 | 本项目当前仍有的差距 |
| --- | --- | --- |
| [MMOInventory 官方文档](https://docs.phoenixdevt.fr/mmoinventory/) | 自定义玩家库存、MMO 系列兼容、纹理、鞘翅槽、MMOItems/Oraxen 集成与事件 API | 尚无完整 MMOItems 装备限制/物品识别桥接、原版装备槽与纹理体验 |
| [CuriosPaper 作者仓库](https://github.com/Brothergaming52/CuriosPaper) | 装备/卸下/替换事件、死亡策略、查询 API、游戏内编辑器、3D 佩戴模型、Geyser、配方/掉落/交易、多存储后端 | 本轮补了事件、死亡与 Profile 基础；仍缺游戏内编辑器、佩戴外观、基岩客户端适配和完整物品产出生态 |
| [DoJewelry 作者发布页](https://www.minebbs.com/resources/dojewelry.16664/) | 发布页搜索索引列出 AttributePlus、槽位解锁、金币/点券/物品消耗、YAML/MySQL；完整页面未成功提取 | Profile/槽位 API 已能接入群体限制；仍缺每玩家永久解锁记录、扣费事务和购买流程 |

本项目现有优势方向是群体可定制背包、显式属性来源、MythicMobs 技能以及可取消的规则入口。下一步更有价值的扩展是永久槽位成长、存储备份恢复工具和成熟物品生态集成。

## 剩余边界

- 玩家原生背包和插件饰品数据没有共同事务。突然断电/进程崩溃仍可能丢失最近未保存操作，或出现两个存储系统状态不一致；未做真实进程崩溃测试。
- 写入故障快照保留在内存中；若存储一直不可写并最终退出进程，没有独立持久化恢复日志。
- MySQL 只有单服有序读写，没有跨服租约、CAS 或交接握手，不能承诺多服同时修改安全。
- 冷缓存同步 API 会等 I/O，慢数据库可能阻塞主线程；常规打开/登录使用异步加载，尚未并发压测。
- 每玩家永久解锁和经济购买尚未实现；技能冷却不跨进程持久化。
- 仍需真实 Paper 双客户端检查所有点击/拖拽/掉落、所有者退出、属性插件切换、Mythic 免死/攻击链、带 PDC/NBT 物品和真实数据库断连恢复。

上述限制保留为明确验收边界，没有将“编译通过”描述为所有实服场景已经完整验证。
